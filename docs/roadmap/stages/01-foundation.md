# Этап 1. Фундамент

Общие куски, без которых денежный сценарий нельзя проверить. Бизнес-потоки — этап 3. Вопросы Q1, Q2, Q8 должны быть приняты (или взят их вариант по умолчанию) до T-1.2 и T-1.5.

### T-1.1: Схема подписчика и попытки списания
- Модуль: domain, cross-cutting
- Требования: REQ-AUD-001
- Файлы ТЗ для контекста: `docs/spec/02-domain-model.md`, `docs/spec/03-cross-cutting.md`
- Зависит от: T-0.2
- Затрагиваемые слои: Domain / Infrastructure
- Размер: M
- Что сделать:
  - Миграция подписчика: `subscriberId`, статус, время создания и смены статуса.
  - Миграция попытки списания: статус, `externalTrxId` (уникальный), `referenceId` (пустой, пока нет успеха), timestamp, ссылка на подписчика.
  - Уникальность `externalTrxId` в БД.
- Критерии приёмки:
  - Повторная вставка того же `externalTrxId` не создаёт вторую строку.
  - Пустой `referenceId` допустим для неуспешной попытки.
- Тесты: integration — миграция накатывается; уникальный индекс отклоняет дубль ключа.
- Сценарии сбоев: обрыв транзакции записи попытки откатывает и подписчика, если они пишутся вместе. Повтор той же вставки не плодит строки.
- Статус: todo

### T-1.2: Валидация MSISDN и суммы
- Модуль: cross-cutting
- Требования: REQ-SEC-003, REQ-SEC-004, REQ-SEC-006
- Файлы ТЗ для контекста: `docs/spec/03-cross-cutting.md`, `docs/spec/open-questions.md` (Q8)
- Зависит от: T-0.2
- Затрагиваемые слои: Domain
- Размер: S
- Что сделать:
  - Value object идентификатора абонента по правилу из принятого Q8.
  - Value object суммы: ровно 2 знака после точки, не float.
  - Мусор на границе отвергается исключением, без обращения к Platform.
- Критерии приёмки:
  - `tel:1000000001` и принятый формат alias проходят.
  - Строка без `tel:`, пустая строка, сумма `5`, `5.0`, `5.000` отклоняются.
  - Код не вырезает из идентификатора «номер телефона» отдельным правилом страны.
- Тесты: unit — границы формата и суммы, включая alias, который нельзя разбирать как телефон.
- Сценарии сбоев: нет внешнего вызова.
- Статус: todo

### T-1.3: Классификация кодов Platform
- Модуль: charging
- Требования: REQ-CHG-004, REQ-CHG-005, REQ-CHG-010, REQ-CHG-011, REQ-CHG-012
- Файлы ТЗ для контекста: `docs/spec/modules/charging.md`
- Зависит от: T-0.2
- Затрагиваемые слои: Domain
- Размер: S
- Что сделать:
  - Разобрать таблицу §E в код: `S1000` terminal-ok; `E1337` и `E1308` non-retry-able; `E1326` и `E1318` retry-able.
  - Отметить последствия, которые ТЗ называет прямо: `E1308` → suspend, `E1326` → grace/retry, `E1318` → throttle/backoff.
  - Неизвестный код не считать retry-able.
- Критерии приёмки:
  - Класс каждого кода из таблицы совпадает с §E.
  - Неизвестный код не попадает в retry.
- Тесты: unit — все пять кодов и один неизвестный.
- Сценарии сбоев: нет сети. Политика чисел retry — в T-3.4 / T-3.5 после Q3.
- Статус: todo

### T-1.4: HTTP-клиент Platform
- Модуль: integrations, sms, opt-in, charging
- Требования: REQ-SEC-001, REQ-SEC-002, REQ-SEC-005, REQ-SEC-006, REQ-API-001, REQ-API-002, REQ-OPTIN-002, REQ-SMS-001, REQ-CHG-013
- Файлы ТЗ для контекста: `docs/spec/04-integrations.md`, `docs/spec/03-cross-cutting.md`, `docs/spec/modules/opt-in.md`, `docs/spec/modules/sms.md`, `docs/spec/modules/charging.md`
- Зависит от: T-0.2
- Затрагиваемые слои: Application / Infrastructure
- Размер: M
- Что сделать:
  - Клиент трёх POST: `/subscription/send`, `/sms/send`, `/caas/direct/debit`.
  - `applicationId` и `password` только из env, в логах их нет.
  - Явные connect/read timeouts (A-TIMEOUTS). Тело — JSON.
  - Разбор ответа: обязательны `statusCode` и `statusDetail`.
- Критерии приёмки:
  - Запрос opt-in содержит `action:"1"`, `version:"1.0"`, идентификатор абонента.
  - Запрос SMS содержит `encoding:"0"` и `destinationAddresses` массивом.
  - Запрос debit содержит поля §D, включая `paymentInstrumentName` `"Mobile Account"` (A-INSTRUMENT).
  - Пароль не попадает в лог при успехе и при ошибке.
- Тесты: unit — сборка тел и редактирование логов на фейковом транспорте; таймаут транспорта становится ошибкой клиента, без повтора внутри клиента.
- Сценарии сбоев: транспорт недоступен или медленнее таймаута → ошибка наружу, без второго запроса. Клиент сам не подменяет `externalTrxId`.
- Статус: todo

### T-1.5: Ключ externalTrxId на billing day
- Модуль: charging
- Требования: REQ-CHG-002, REQ-CHG-008, REQ-CHG-009
- Файлы ТЗ для контекста: `docs/spec/modules/charging.md`, `docs/spec/open-questions.md` (Q1)
- Зависит от: T-1.2
- Затрагиваемые слои: Domain
- Размер: S
- Что сделать:
  - Функция ключа: один и тот же подписчик и тот же billing day (Q1) всегда дают один и тот же `externalTrxId`.
  - Другой день или другой `subscriberId` даёт другой ключ.
  - Ключ не содержит номер попытки.
- Критерии приёмки:
  - Повтор вызова в тот же день стабилен.
  - Смена даты или абонента меняет ключ.
  - В ключе нет секрета Platform.
- Тесты: unit — стабильность, смена дня, смена абонента, время через подставные часы, не через системные.
- Сценарии сбоев: нет. Объяснение ключа для человека пишется в T-4.2 (REQ-CHG-008).
- Статус: todo
