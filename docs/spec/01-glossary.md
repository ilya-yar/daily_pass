Термины в формулировках ТЗ. Где ТЗ не даёт определения, стоит пометка.

| Термин | Смысл в ТЗ |
|---|---|
| Daily Pass | Продукт: платная ежедневная подписка (строка 18). |
| Carrier Platform, Platform | Биллинговый шлюз оператора. Единственный контракт — Appendix, строки 136–199. |
| `service/` | Наш subscription service (строка 24). |
| `platform-mock/` | Локальный мок Platform (строки 25–28). |
| MSISDN | Номер абонента, который принимает точка opt-in (строка 40). Формат валидации: `tel:` + digits (строка 79). |
| `subscriberId` | Идентификатор абонента в API Platform. В примерах `tel:1000000001`. Может быть стабильным masked alias, а не настоящим номером (строки 81–82). |
| masked alias | Стабильный псевдоним вместо реального номера. Из него нельзя восстанавливать телефон (строки 81–82). |
| MT | Исходящая SMS от сервиса к абоненту: welcome, receipt, goodbye. `POST /sms/send` (§C). |
| MO | Входящая SMS от абонента на shortcode. Для opt-out текст `STOP` (§C, F4). |
| billing day | Сутки, внутри которых дневная плата списывается не больше одного раза (F3, строки 52–58, 73–74). Граница суток в ТЗ не задана. Принятый Q1: календарная дата UTC. |
| Direct Debit | `POST /caas/direct/debit` — списание с Mobile Account (§D). |
| `externalTrxId` | Наш id запроса Direct Debit. Ключ идемпотентности Platform: тот же ключ — дубль (`E1337`), новый ключ — второе списание (строки 174, 185–186). |
| `referenceId` | Идентификатор успешного списания в ответе Platform. Его нужно включить в SMS receipt (F3, строка 55; §D строка 183). |
| `internalTrxId` | Поле успешного ответа Direct Debit (строка 182). В списке обязательных полей аудита (строка 83) его нет. |
| `requestId` | Поле ответа `POST /subscription/send` (строка 152). Обязательность хранения не задана. |
| ACTIVE | Локальный статус после opt-in (строка 41). Таких подписчиков берёт дневной job (строка 52). |
| INACTIVE | Локальный статус после opt-out (строка 62). После этого списывать нельзя (строки 63–64). |
| suspend | Действие на `E1308`: приостановить подписчика (строки 57, 194). Отдельное имя статуса в ТЗ не задано. Принятый Q4: статус `SUSPENDED`. |
| REGISTERED / UNREGISTERED | `subscriptionStatus` в ответе §A и значения `status` webhook §B. |
| PENDING / CHARGE | Допустимые значения `status` webhook §B (строка 159). Отдельная обработка, кроме «handle at least REGISTERED and UNREGISTERED», не описана. Принятый Q5: только сохранить событие и ответить `S1000`. |
| grace / retry | Политика для `E1326` (недостаток баланса, transient). Числа попыток и паузы не заданы. Принятый Q3: не больше 3 попыток, пауза 1/2/4 с, тот же `externalTrxId`. |
| `applicationId` / `password` | Учётные данные Platform в JSON body каждого исходящего запроса. Из config/env, не в коде и не в логах (строки 78, 141). |
| statusCode / statusDetail | Есть в каждом ответе Platform (строка 143) и в наших ответах на webhook и MO. |
| S1000, E1337, E1308, E1326, E1318 | Коды §E. Таблица — в `modules/charging.md`. |
